čekaj malo, još smo na ADR fajlu - ne kodiramo još.
Nije dovoljno dobro. nije dovoljno detaljno. Idemo skroz PREPISATI ADR FILE sa ovim JAKO DETALJNIM GUIDEOM- ovo je skroz low level. SKROZ low level template.

Evo kako želim da naš template file izgleda.

Prvo ćemo na vrhu imati iskomentirano dokumentaciju o templateu
u dokumentaciji ćemo prvo spomenuti markere unutar dvije zagrade i njihove default vrijednosti te koje su obavezne a koje nisu
zatim isto u dokumentaciji ćemo spomenuti varijable unutar tri zagrade - to su vrijednosti izbačene iz našeg apija, a ubačene u template na taj način.
osim varijabli imat ćemo i neke liste poput {{directory_tree}} i {{file_content}} koje bi nekako ljepše trebalo opisati ali ja to ne znam kako budući da će nam za directory tree trebati mogućnost da definiramo kakve opcije nam moraju pisati uz fajlove i foldere tamo. s tim dijelom mi moraš pomoći. ovaj templating jezik je stvar za sebe , molim te da detaljno pričamo o njemu i da mi SUGERIRAŠ rješenja za templating prije nego što napišemo templating ADR. Zatim kada se dogovorimo idemo napisati detaljan templating ADR

Ovo je ideja kako želim da otprilike izgleda template koji user može editirati. sintaksu i file format ti odluči
--template-start--

#[documentation start]
#define your markers here
#available markers (see docs)
#use ";" for space in templating

#{{start_marker_open}} defines opening of the start marker such as in html "<"; can be empty; default = "<"
#{{start_marker_close}} defines closing of the start marker such as in html ">"; can be empty; default = ">"
#{{end_marker_open}} defines opening of the end marker such as in html "</"; can be empty; default = "</"
#{{end_marker_close}} defines closing of the end marker such as in html ">"; can be empty; default = ">"

#{{directory_tree_start_marker}} at the start of directory tree; required; default = "DIRECTORY_TREE"
#{{directory_tree_end_marker}} at the end of directory tree ; required; default = "DIRECTORY_TREE"

#{{instructions_marker_start}} at the start of instructions section; required; default ="INSTRUCTIONS"
#{{instructions_marker_end}} at the end of instructions section; required; default ="INSTRUCTIONS"

#{{file_size_marker}}="SIZE"
#{{file_id_marker}}="ID" - used for file and folder ID; shortened for clarity
#{{file_path_marker}}="PATH"
#{{line_count_marker}}="LINES"
#{{mod_marker}}="MOD"

#{{file_content_start_marker}} at the start of the file content section; required; default = "FILE_CONTENT_START"
#{{file_content_end_marker}} at the end of the file content section; required; default = "FILE_CONTENT_END"

##available variables
#{{{file_id}}} incremental file ID ; root folder's id is ROOT, D is for directories, F is for files
#{{{file_path}}} file path relative to the root of the project
#{{{file_size}}} file size in bytes
#{{{line_count}}} number of lines in a document
#{{{mod}}} last modified timestamp

(instructions je polje koje referira prethodno definirane varijable i zato njega moramo definirati na kraju)
#{{instructions}} detailed set of instructions about the LLM context; required; supports new line via ""; default= "Manifest: The {{directory_tree_start_marker}} section below lists all files and directories.- Each entry: [TYPE] RELATIVE_PATH ({{file_id_marker}}:UNIQUE_ID, {{mod_marker}}:UNIX_TIMESTAMP, {{file_size_marker}}:BYTES)- TYPE is [D] for directory, [F] for file.- {{file_size_marker}} is for files only.- Binary files may be noted with (CONTENT:BINARY_HINT or CONTENT:BINARY_PLACEHOLDER).\2. Content Access: To read a specific file:- Find its UNIQUE_ID from the DIRECTORY_TREE - Search for the marker: {{start_marker_open}}{{file_content_start_marker}} {{file_id_marker}}="UNIQUE_ID"{{start_marker_close}}- The content is between this marker and {{end_marker_open}}{{file_content_end_marker}} {{file_id_marker}}="UNIQUE_ID"{{end_marker_close}}"
#[documentation end]

#[marker definitions start] (ovo je sekcija gdje se definiraju markeri točno kao stringovi)
... tu ispisujemo sve varijable definirane u njihovim default values kao što sam gore naveo u [documentation] sectionu; neću pisati sve radi kratkoće; npr:
{{start_marker_open}}="<"
{{start_marker_close}}=">"
...
{{directory_tree_start_marker}} ="<DIRECTORY_TREE>"
...
svi markeri iz documentation sectiona
#[marker definitions end]

#[literal template start] - ovdje sada doslovno gradimo template s našim varijablama i markerima
![DCTX_LLM_SNAPSHOT_V{ver}]   (ovo je heading i njega ne možemo mijenjati; V broj se normalno inkrementira po našoj logici)
ovaj dio naslova NE SMIJE biti u templateu, on mora biti hardkodiran u našem projektu pošto ima verziju u sebi što je promijenjiva varijabla i to nećemo ubaciti u template

{{start_marker_open}}{{instructions_marker_start}}{{start_marker_close}}
{{instructions}}
{{end_marker_open}}{{instructions_marker_end}}{{end_marker_close}}

{{directory_tree}} -> uses: {{file_id}} {{mod}}{{size}} ( ovo je lista fajlova i foldera; ali moramo nekako tu moći napisati koje opcije moramo pisati tamo) - nađi način za ovo lijepo definirati u templateu
{{end_marker_open}}{{directory_tree_end_marker}}{{end_marker_close}}

{{#files}} ... također treba lijepo naći načina za raspisati fajl sintaksu, odnosno kako DOSLOVNO ta sekcija izgleda za svaki fajl.

{{start_marker_open}}{{file_content_start_marker}};{{file_id_marker}}="{{{file_id}}};{{line_count_marker}}="{{{line_count}}}"{{start_marker_close}}
{{file_content}}
{{end_marker_open}}{{file_content_end_marker}};{{file_id_marker}}="{{{file_id}}}{{end_marker_close}}
