## 3. IMMEDIATE OBJECTIVE: PHASE 4 (Output Parity & Diffing)

Your task is to implement **ADR-002 (Versioning & Recovery)** and restore output aesthetics to match the legacy C implementation. We need to reduce "noise" in the output and handle massive changes intelligently.

**Specific Tasks (Refer to `PROJECT-DEVELOPMENT-ELABORATION.md`):**

1.  **Aesthetic Restoration:**
    - Update `llm_formatter.rs` to use the legacy header format: `[DIRCONTXT_LLM_SNAPSHOT_V...]`.
    - Implement Semantic IDs: Replace raw integers with `ROOT`, `D1`, `F2`, `F3` (D=Directory, F=File).
    - Implement Visual Indentation in the generated Directory Tree.

2.  **Diff File Generation:**
    - Implement logic to generate `*-diff.txt` files when a minor version bump occurs.
    - These files must contain the *full* tree but *only* the content of modified/added files.

3.  **Advanced Versioning Logic (ADR-002):**
    - **Trigger A (Massive Change):** If `files_unchanged == 0` (complete rewrite), force a Major Version Bump (V1 -> V2).
    - **Trigger B (Diff Limit):** If `minor_version > max_diff_files`, force a Major Version Bump.
    - **Cleanup:** On Major Bump, delete all old `*-diff.txt` files in the output directory.
