# Language coverage

The engine registry in `crates/dctx/src/languages.rs` is authoritative. The table
below is generated by `cargo run -p dctx-cli --locked -- languages --markdown`;
the CLI tests compare it byte for byte with the engine output. Never edit its
rows by hand. The README uses the same generator and drift check.

`full` promises symbols and lexical call edges, `outline` promises symbols,
and `docs` promises headed sections. `guess` means a heuristic extractor;
it does not promise a validating grammar, macro expansion or type resolution.
Most structural lexers abstain on unsupported or incomplete syntax. The
JavaScript/TypeScript path retains accepted partial facts. Unknown extensions
remain module-only.

## Audit corpus

`crates/dctx/tests/fixtures/languages/` contains original Apache-2.0 fixtures,
with one directory for every registry tag. The registry-completeness test fails
when a language is added without fixtures. C and C++, JSX and TSX, Kotlin scripts,
all four configuration formats, and Vue/Svelte/Astro/HTML have separate cases.

`cargo test -p dctx --test language_goldens --locked` checks skeleton records and
reads every extracted declaration, comparing identity, kind, source lines,
signature, summary, confidence, byte span and exact source. The corresponding
reviewable expectations live in `crates/dctx/tests/goldens/languages/`.
Every source is also exercised as CRLF, UTF-8 BOM, BOM with CRLF and with an
additional line over 4 KiB (a comment, document text or legal JSON whitespace).
Reads always use the original physical bytes;
there is no wrapper normalization. Classes, nested named functions, generics,
annotations/attributes and macros appear where the language defines them.
Unicode identifiers appear where legal; other formats use Unicode text/keys.
A document or configuration fixture cannot meaningfully contain a class or a
language macro. Anonymous functions are not promised named symbols.

To refresh expectations after reviewing an intentional engine change:

```sh
DCTX_UPDATE_LANGUAGE_GOLDENS=1 cargo test -p dctx --test language_goldens --locked
```

## Candidate language additions

All seven candidates in this audit request were already registered at the
starting revision: Kotlin, Swift, C#, Ruby and PHP have first-party lexers;
Zig and Elixir have heuristic extractors. There are no three missing candidates
to add, and the repository has no request-frequency data to rank them.

The audit therefore extends the existing Kotlin, Swift and C# lexers to retain
named local functions and their lexical owners. These three already have token
and declaration walkers, so the fixes need no dependencies or optional grammar
features. The optional tree-sitter dependency tree has Rust, JavaScript,
TypeScript and Markdown grammars only. Zig and Elixir retain their documented
`guess` confidence; registering them again or relabelling them structural would
misrepresent coverage.

The heuristic fixtures expose current boundaries as well as positive cases.
For example, Zig's quoted function identifier, R's nested assignment-form
function and Julia's nested long-form function are currently omitted. Macro
invocations are never expanded. These are limitations of the `guess` tier,
not claims of complete syntax coverage; their surrounding declarations and
source reads remain covered by the goldens.
