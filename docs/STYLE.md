# Rust house style

Keep the surrounding source layout, including wide lines when they keep a declaration, match arm, protocol record, or assertion readable as one unit. Prefer small, focused edits over unrelated layout changes. Preserve module headers, explicit boundary types, and behavior; use readable numeric separators and document fallible public operations.

## Formatting and the worker boundary

Rustfmt is not adopted. Its default reflow expands compact source into many more lines and would break the existing plugin-git file-length boundary test. `plugins/dctx-plugin-git/tests/boundary.rs::worker_sources_have_no_direct_effects_and_carry_headers` embeds 23 worker source files and requires each to have at most 300 lines, alongside checks for module headers, unsafe-code policy, and forbidden direct effects. Keep that boundary intact when adding documentation or lint attributes. Split a module deliberately if needed; do not weaken the test to accommodate a formatter.

Do not add `cargo fmt --check` to CI. Formatting is reviewed in context.

## Pedantic style gate

Run the style gate on the remote build host or the dctx CI runner:

```sh
cargo clippy --workspace --all-targets -- -W clippy::pedantic
cargo doc --no-deps
```

Resolve each diagnostic with a genuine improvement or a narrowly scoped attribute of the form `#[allow(clippy::lint_name, reason = "specific justification")]`. Put the allow on the affected function, type, implementation, or test module; avoid blanket crate-level suppression. Keep public API signatures and behavior stable. Keep rustdoc warning-free, and retain the existing CI clippy and test checks before pushing a batch.

Documented exceptions:

- `many_single_char_names` on SHA compression functions: the a-h working variables follow FIPS 180-4 and make comparison with the specification straightforward.
- `must_use_candidate` and `return_self_not_must_use` on existing public constructors, accessors and value operations: preserve the API's existing caller lint behavior while keeping signatures and runtime behavior stable. Existing `#[must_use]` contracts remain in force.
- `struct_field_names` on the Rust extractor's limits and Markdown block collection: `max` distinguishes ceilings from observed counts, while `code_blocks` matches the public document vocabulary.
- `cast_possible_truncation` and `cast_possible_wrap` on bounded lexer helpers: the public code extractors clamp input to 8 MiB, keeping source coordinates, token counts and nesting within their integer representations. Markdown ATX levels are checked against 1 through 6. Each function states its applicable bound.
- `cast_possible_truncation` on deterministic fuzz-length selection: preserve the generator's intentional native-word truncation before its 301-byte modulus. Generated bytes use the explicit low byte; bounded test coordinates use checked conversions.
- `cast_possible_truncation` and `cast_possible_wrap` on Linux platform helpers: chunks are bounded by the 16 KiB buffer, parent PIDs are range-checked by the constructor, and kernel timestamp nanoseconds fit `i64`.
- `cast_precision_loss` on differential scoring and binary classification: fixed fixture counts fit the exact integer range of `f64`; classification samples at most 8,192 bytes.
- `needless_pass_by_value` on existing public capability/configuration entry points and the Go error assertion helper: retain their value-taking contracts. Configuration-parser dispatch transfers pending comment ownership to the item being handled.
- `unnecessary_wraps` on the Unix file-index hook: its shared platform interface returns `None` when inode metadata is unavailable. `unused_self` on the C/C++ skipped-span hook keeps recovery operations on the walker.
- `option_option` on YAML leading-comment extraction: the outer option means the block continues; the inner option contains its optional comment. `struct_excessive_bools` on Kotlin modifiers and configuration draft facts retains independent syntax facts, including malformed modifier combinations.
- `too_many_lines` on ordered grammar dispatches, fact assembly and golden-fixture tables: keep shared cursor/recovery state or expected records beside their checks. The plugin-git source-file boundary remains separate and unchanged.
- `similar_names` for established scanner/output roles and related regression fixtures, `many_single_char_names` for the JavaScript score table's emitted/expected sets and matched/emitted/expected counts, and `fn_params_excessive_bools` for the Python fixture generator's independent f-string dimensions.
- `case_sensitive_file_extension_comparisons` on checked-in JavaScript oracle fixture paths preserves their literal suffix selection. `naive_bytecount` on a bounded JavaScript error path uses standard iterators without adding a dependency.

Additional scoped exceptions in the map, storage, template and desktop API crates:

- `trivially_copy_pass_by_ref` for Serde field predicates and eight-byte envelope magic: the callback requires a reference, and codec inputs consistently borrow byte views.
- `struct_excessive_bools` for independent ranking boosts and serialized desktop preferences: all combinations are meaningful, and the public input/configuration format stays stable.
- `verbose_bit_mask` on canonical varint decoding: `0x7f` explicitly names the seven payload bits and matches the encoder.
- Numeric casts retain explicit local bounds: 120/400-line source pages, a 40-row SQL limit, a 999-point degree boost, 8 MiB parser inputs and line counts clamped to `u32::MAX`. Floating ranking scores are rounded and clamped; desktop size thresholds reject non-finite/non-positive values, saturate at the upper boundary and intentionally truncate fractional bytes. Resolver duplicate ordinals use checked conversion and addition instead of narrowing silently.
- `case_sensitive_file_extension_comparisons` preserves literal language-dispatch and privacy suffix policies; folding case would change which paths are parsed or denied.
- `unnecessary_debug_formatting` preserves quoted, escaped corpus paths in test reports. `naive_bytecount` keeps renderer newline conventions and fixture checks on standard iterators without another dependency.
- `field_reassign_with_default` keeps configuration regressions anchored to the public defaults and makes successive validation transitions explicit. `similar_names` retains codec/fixture role names. `too_many_lines` keeps graph transactions, source-ordered dispatches and their acceptance fixtures together.
- Public value-taking publication/lease operations keep their ownership contracts. `implicit_hasher` preserves the v1 template replacement API and its documented default-hasher iteration contract.

The workspace-wide pedantic cleanup is being landed in crate-sized batches. The command above is the house style gate; the current CI workflow still runs its existing `-D warnings` clippy command and tests. The full workspace includes the Tauri desktop app and needs its platform development libraries. A run with `--exclude dctx-desktop` is useful for the other crates but does not establish full-workspace acceptance.

The current Linux cleanup excludes `dctx-desktop`, as CI does. Use `--workspace --exclude dctx-desktop` for both commands on that host; desktop validation needs its GLib/GObject/GIO development libraries. Keep the exclusion explicit in validation receipts and completion reports.
