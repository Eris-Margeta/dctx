# Interrupted cache publication and reopen

Base `ae4944fa1a0c5ecc3cc5c7f0030ca6d2840d5115`. This is a source audit. The Rust tests and TLC configurations below are existing coverage inspected at that revision. The card check validates the source references.

Two readers make different recovery decisions. A reusable session snapshot follows the current view in `ledger.v1` and rebuilds from source on a missing object. A cold map index checks both segment-store pointers and can serve the previous complete journal. The strongest gaps are the on-disk ordering of directory entries across power loss and the protection of leased files when another opener collects them. The evidence for each case follows.

## Managed snapshot and ledger

**Publication and reopen · high confidence.** The session encodes the reusable generation and passes its bytes to the managed store. Under the exclusive ledger lock, admission loads the latest image, inserts the segment, switches the working view, confirms a lease, writes the segment and its `dctxview1` manifest under numeric object names, and takes the liveness lock. The view drops its previous pointer in the working image. The rename of the synced, checksum-checked temp to `ledger.v1` switches the committed image. Other coordinated readers can observe it once the exclusive lock is released, including if the writer exits. A power loss between rename and root-directory sync leaves persistence of the rename uncertain. A fresh session loads that committed image. The reader holds the shared lock through both file reads, verifies the decoded generation against the request and source inventory, then rechecks the generation under the exclusive lock before pinning it. A replacement between read and pin cannot give the caller a lease on the wrong bytes. The stale-inventory test checks exactly that refusal. Interruption after an eviction unlink leaves the old ledger charging a missing retired file. This is a separate cut from loss of a current payload. The disk test checks successful eviction and reload. It does not interrupt between unlink and commit. **Object names across power loss · high confidence in the missing sync, conditional impact.** Object publication syncs the temp file, hard-links its final name in `objects/`, and removes the temp. Ledger publication later syncs the cache root on Unix. Neither step explicitly syncs the modified `objects/` directory. A power interruption can therefore leave a committed ledger naming a missing payload on filesystems requiring a parent-directory sync. The expected consequence is the cache miss above. The process-reopen fixtures do not establish which names survive storage rollback. See `crates/dctx-adapter-cache/src/adapters/cache.rs:55`, `crates/dctx-adapter-cache/src/adapters/mod.rs:610`, `crates/dctx-adapter-cache/src/adapters/publish.rs:27`, `crates/dctx-adapter-cache/src/adapters/mod.rs:205`, `crates/dctx-adapter-cache/src/adapters/mod.rs:624`.

**Lease acquisition during explicit reclaim · high confidence in the ordering, inferred race.** A purge or GC can load an unleased generation, prepare its removal, and pause. A second session can then commit a lease. The first session physically unlinks the files before its stale ledger store is rejected. A retry can observe the lease, but the named bytes are already gone. The sequential handle test above acquires the lease before purge loads. It cannot detect this interval. ## Map journal, segment pointers and SQLite

**Publication and cold open · high confidence.** `Index::open` opens SQLite and the sibling segment directory. Refresh publishes a journal with `writing=true`, applies the source snapshot, then publishes the finished journal. Each publication prepares fact and view blobs, decodes and hashes them, installs immutable segments and a manifest naming their roles, sizes and digests, retains the old current pointer as previous, and replaces current with the new generation, manifest digest and length. A fresh process recovers, pins a validated generation, decodes its journal and releases the short pin. An interrupted journal sets the index unready so the next query refreshes. The SQLite graph uses per-file transactions. ## What the model establishes

**Model scope · high confidence.** The pass configuration bounds acquisition and crash to one each. Swap installs the new pointer in one action. Recovery discards unpublished state or preserves a swapped pointer. P2 requires valid segment and manifest for a visible successor. P3 protects the old generation while leased or retained for recovery. P8 requires progress under fairness. The pointer-first, omit-leases and stuck-writer mutants target those properties. Its single root, reader and successor share one state. Loss of a child directory entry and collection by an independently opened store lie outside that state space. The Rust lifecycle tests simulate death before and after swap, including encode/decode with injected held-session evidence. A disk-ledger round trip also injects the session evidence. These tests check logical state and charges, while the filesystem fixtures above read actual payload bytes. See `docs/formal/dctx-cache/CacheLifecycle.cfg:14`, `docs/formal/dctx-cache/CacheLifecycle.tla:200`, `docs/formal/dctx-cache/CacheLifecycle.tla:219`, `docs/formal/dctx-cache/CacheLifecycle.tla:240`, `docs/formal/dctx-cache/CacheLifecycle.tla:395`, `docs/formal/dctx-cache/CacheLifecycle.tla:403`, `docs/formal/dctx-cache/CacheLifecycle.tla:444`, `docs/formal/dctx-cache/README.md:12`, `docs/formal/dctx-cache/README.md:37`, `crates/dctx-adapter-cache/tests/recovery.rs:55`, `crates/dctx-adapter-cache/tests/recovery.rs:82`, `crates/dctx-adapter-cache/tests/recovery.rs:219`, `crates/dctx-adapter-cache/tests/dctx_adapter_cache.rs:73`.
