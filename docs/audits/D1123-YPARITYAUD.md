# Python, Go and Node transport parity

**Base** `ae4944fa1a0c5ecc3cc5c7f0030ca6d2840d5115`. All three clients forward the 15 advertised operations to the same Rust dispatcher. The strongest parity evidence is exact CLI stdout on a shared two-line Rust fixture. Two differences matter even with the correct binary: JSON escaping changes which requests fit on the wire, and an RPC caller cannot obtain the CLI's standalone pack schema through the pack operation. Named context, source spans and genuine partial pages have more engine-level coverage than wrapper-level coverage.

This is a read-only audit of implementation, fixtures and workflow definitions. The binary-backed tests below are identified by the executable they invoke and the assertions they make. No engines, package suites, CI runs or release services were launched for this audit.

## Differences and untested conditions

1. **The same valid argument can reach the engine from only some bindings. High confidence from the encoders.** For `languages("--help", "λ" repeated 200000 times)`, Python's ASCII-escaped JSON needs 1,200,000 bytes just for the repeated argument. Go and Node need 400,000 plus a small envelope. Python refuses locally, while the other two fit and the engine returns help before inspecting the padding. With 200000 ampersands the default Go JSON HTML escaping makes Go the outlier. The protocol limit is 1,048,576 encoded bytes before LF. Even ID representation contributes at the exact boundary. Existing invalid-size tests use already-oversized inputs in each language and do not compare the same near-limit argument across bindings. `packages/python/src/dctx/_client.py:75`, `packages/go/client.go:197`, `packaging/npm/dctx/src/index.js:90`, `docs/protocol/README.md:81`, `crates/dctx-cli/src/languages.rs:79`, `packages/python/tests/test_transport.py:289`, `packages/go/client_test.go:241`, `packaging/npm/test/client.test.cjs:83`.

2. **The standalone CLI pack schema is unreachable via RPC pack. High confidence from dispatch.** `dctx pack --schema` returns the schema without reading a project. All three bindings forward `pack(["--schema"])` through RPC, which prepends `--json`. The special case needs exactly two words including `pack`, so parsing reaches “unknown pack flag” and returns code 2. This concerns a public CLI flag that already emits JSON. The three clients agree on the refusal. The general pack-to-CLI comparison in the suites misses it. `crates/dctx-cli/src/pack.rs:93`, `crates/dctx-cli/src/rpc/mod.rs:197`, `crates/dctx-cli/src/pack.rs:280`, `crates/dctx-cli/src/pack.rs:292`, `crates/dctx-cli/src/pack.rs:633`, `docs/protocol/README.md:29`.

3. **Every-verb coverage misses named context and mixed-result batches. High confidence.** All three wrapper tables exercise task context and map their CLI oracle for *every* context request to `pack`. The dispatcher also accepts named targets. Raw CLI/RPC tests check a golden, repeated references and isolation between session names. With `context ping missing_target --session s --dedupe`, the engine accumulates both pages, commits history and returns code 1 with the accumulated stdout. A subsequent `ping` on that connection can refer to the successful chunk inside the earlier error output. A fresh CLI process returns full content. A caller discarding failure stdout can therefore lose the only full copy. No wrapper table exercises this sequence. The Python README also says context requires `--for` and a pack status line may follow the JSON. Go directs context callers to `--for`. The schema description still calls context an alias. `packages/python/tests/test_parity.py:40`, `packages/python/tests/test_parity.py:47`, `packages/go/parity_test.go:68`, `packaging/npm/test/parity.test.cjs:56`, `crates/dctx-cli/src/rpc/mod.rs:202`, `crates/dctx-cli/tests/context_surfaces.rs:128`, `crates/dctx-cli/src/context_cmd.rs:47`, `crates/dctx-cli/src/context_cmd.rs:70`, `crates/dctx/src/context/chunks.rs:95`, `docs/CONTEXT.md:66`, `packages/python/README.md:47`, `packages/go/README.md:54`, `docs/protocol/dctx-rpc-v1.schema.json:222`, `crates/dctx-cli/tests/pack_cli.rs:147`.

4. **The common fixture establishes byte identity on a narrow range of pages. High confidence.** The read golden has lines `[1,2]`, span `[0,30]`, ASCII source and a final LF. The other golden is an empty find. CI runs these against CLI and raw RPC only. The wrappers independently compare the live CLI on the same fixture. Rust facade tests exercise CRLF, multibyte source and no final LF. Rust CLI graph tests force `truncated:true` on populated graphs. Wrapper rows use one isolated function, a bounded no-path trace and empty impact. They do not require a nonempty truncated answer, exercise a returned cursor, require `precision.completion` of `partial` or `refused`, or read Unicode spans on disk. Those inner labels describe extraction and can appear in a successful page. They are distinct from an RPC error code. Zero-byte success with `pack --output` and exact real-engine Node diagnostic text also lack wrapper assertions in these rows. A lost cursor, byte-to-character conversion, discarded empty string or altered hint could escape the relevant tests. Clipboard behavior was untested. `crates/dctx/tests/fixtures/repository/src/lib.rs:1`, `tools/engine-contract/goldens/read-lines.json.golden:1`, `tools/engine-contract/goldens/cases.json:9`, `.github/workflows/ci.yml:155`, `tools/engine-contract/parity.py:94`, `crates/dctx/tests/span_index.rs:24`, `crates/dctx-cli/tests/answer_verbs.rs:130`, `docs/guides/MAP-MODE.md:265`, `packages/python/tests/test_parity.py:25`, `packages/go/parity_test.go:133`, `packaging/npm/test/parity.test.cjs:44`, `packaging/npm/test/parity.test.cjs:70`.

5. **The public schema excludes a real protocol refusal. High confidence.** An unparseable or oversized raw request yields a required `id` whose value is null, with code 2 and empty output. The committed schema describes null but permits only string and integer. The exported TypeScript wire `Response` inherits that union, while Python's generated response types explicitly include `None` and Go retains the raw ID. A schema validator or typed raw-stdio consumer can reject a legitimate refusal. Ordinary high-level calls allocate their own valid IDs and correctly treat an uncorrelatable reply as a transport failure. Schema regeneration equality alone cannot detect this mismatch. `docs/protocol/README.md:24`, `crates/dctx-cli/src/rpc/mod.rs:105`, `crates/dctx/src/rpc.rs:170`, `docs/protocol/dctx-rpc-v1.schema.json:163`, `packaging/npm/dctx/src/protocol.d.ts:18`, `packages/python/src/dctx/_generated.py:43`, `packages/go/api_generated.go:58`, `crates/dctx-cli/tests/rpc.rs:76`.

6. **A damaged response stream can produce a result in Node. High confidence in the reader difference, inferred consequence.** Python requires LF and strictly decodes UTF-8. Go requires LF and explicitly validates UTF-8. Node uses a text readline interface and resolves at the line event. An otherwise complete final JSON object without LF can resolve a pending operation before the close handler records the exit. An invalid raw UTF-8 byte inside a quoted output string can become a replacement character and pass the string check. These are faulty-interpreter or interrupted-stream conditions. The conforming Rust writer emits valid JSON followed by LF. Node's malformed-JSON and exit fixtures do not exercise either case. `packages/python/src/dctx/_client.py:85`, `packages/go/client.go:209`, `packaging/npm/dctx/src/index.js:37`, `packaging/npm/dctx/src/index.js:44`, `packaging/npm/dctx/src/index.js:79`, `packaging/npm/test/client.test.cjs:58`, `crates/dctx-cli/src/rpc/mod.rs:114`.
