# Which engine tests run on a push to main?

At revision `bd82ecf497cc`, a green quality job can skip all four `WireEnvelopes` methods. It discovers the class before building the CLI and supplies neither engine variable. The same job later requires four real CLI/RPC golden comparisons. Go, Python and Node also have real-engine gates, but their test commands select their own package suites. A successful schema-change judge run establishes that the wire suite *can* pass with a binary. It supplies no execution evidence for that suite on a push. See `.github/workflows/ci.yml:108`, `tools/engine-contract/test_wire_envelopes.py:23`, `.github/workflows/ci.yml:185`, `.github/workflows/go.yml:95`, `.github/workflows/python-packages.yml:59`, `.github/workflows/python-packages.yml:127` and `.github/workflows/npm.yml:65`.

## The quality job, in execution order

1. A main push selects quality by default on hosted Ubuntu 24.04. Setup selects Python 3.12 and the pinned CI Rust toolchain. After formatting, `python3` creates the engine venv, its pip installs the requirements, and its bin directory goes on `GITHUB_PATH` for subsequent steps. The pin for `jsonschema` is 4.26.0. The wire module imports its Draft 7 validator **before** class setup, so a missing dependency causes a discovery error even when the engine is optional. See `.github/workflows/ci.yml:7`, `.github/workflows/ci.yml:39`, `.github/workflows/ci.yml:73`, `.github/workflows/ci.yml:83`, `tools/release/toolchain.env:6`, `.github/workflows/ci.yml:102`, `scripts/requirements.txt:2` and `tools/engine-contract/test_wire_envelopes.py:11`.
2. The venv's `python3` runs the import-boundary scan, then `python3 -m unittest discover -s tools/engine-contract -p 'test_*.py' -v`. The workflow environment sets only Cargo color. A restored executable alone cannot enable the class because setup reads only `DCTX_TEST_BIN`. When it is empty, setup raises one class-level skip unless `DCTX_REQUIRE_ENGINE_TESTS` is exactly `1`, in which case it raises an assertion. The other discovered module runs nine import guards, one golden-comparator guard using supplied byte values, and four trace guards using synthetic traces or mocks. See `.github/workflows/ci.yml:35`, `.github/workflows/ci.yml:91`, `.github/workflows/ci.yml:110`, `tools/engine-contract/test_wire_envelopes.py:24`, `tools/engine-contract/test_contract.py:15`, `tools/engine-contract/test_contract.py:96` and `tools/engine-contract/test_contract.py:106`.
3. After lint, documentation and policy checks, quality builds `cargo build --release --locked -p dctx-cli`. The venv's `python3 tools/engine-contract/parity.py target/release/dctx-cli` takes its binary as a positional argument. It runs the fixture's line read and empty find via direct CLI and via a hello plus RPC call. CLI stdout and decoded RPC result output must each match the committed bytes, including final newlines. Two cases × two surfaces = four comparisons. No adapter is supplied. An empty corpus, spawn error, timeout, nonzero exit, stderr, bad handshake/ID or byte mismatch fails the step. This validates successful payloads and selected envelope fields. The script never applies the Draft 7 validator to refusal frames. See `.github/workflows/ci.yml:146`, `.github/workflows/ci.yml:187`, `.github/workflows/ci.yml:190`, `tools/engine-contract/goldens/cases.json:3`, `tools/engine-contract/goldens/cases.json:9`, `tools/engine-contract/parity.py:24`, `tools/engine-contract/parity.py:53`, `tools/engine-contract/parity.py:77` and `tools/engine-contract/parity.py:89`.

## Local reproduction

Run from the checkout root with the supplied RAM target and caches. The local Linux run used Python 3.13.5, the installed jsonschema 4.19.2, and Rust/Cargo 1.100.0. The initial offline build could not resolve `schemars` in the card's empty Cargo registry. The commands below select the existing populated registry, without a download or a change to the build target. Hosted quality uses Python 3.12, its pinned validator and the release profile. The matrix above is a trace of the checked-in workflows conditional on earlier steps passing. No hosted run logs or cross-platform executions were sampled. See `rust-toolchain.toml:2`, `.github/workflows/ci.yml:73`, `.github/workflows/ci.yml:102`, `scripts/requirements.txt:2` and `.github/workflows/ci.yml:187`.

```bash
umask 022
wire=(python3 -B -m unittest discover -s tools/engine-contract -p test_wire_envelopes.py -v)
env -u DCTX_TEST_BIN -u DCTX_REQUIRE_ENGINE_TESTS "${wire[@]}"
env -u DCTX_TEST_BIN DCTX_REQUIRE_ENGINE_TESTS=1 "${wire[@]}"
DCTX_TEST_BIN=$'absent-wire-cli\n\x1b"' DCTX_REQUIRE_ENGINE_TESTS=1 "${wire[@]}"

export CARGO_HOME="$HOME/.cargo" RUSTC_WRAPPER=
cargo build --offline --locked -p dctx-cli
DCTX_REQUIRE_ENGINE_TESTS=1 DCTX_TEST_BIN="${CARGO_TARGET_DIR:-target}/debug/dctx-cli" "${wire[@]}"
```
