CLI reference

Captured from dctx 1.3.0 when this site was built; a check fails the build when the binary prints anything else. Help text is shown verbatim, so it is the CLI's own wording, including the legacy snapshot options it still lists.

What the output looks like#

These are real runs on the tiny kiosk sample, captured by capture.py from the release binary. Commands run inside a copy named kiosk. For source builds, the executable is dctx-cli (or define a dctx alias).

Find a symbol, then read it#

Pass the exact ID from find to read to get its metadata and verified source bytes:

$ dctx map find greet
# kiosk find
s:src/util.rs#greet fn  L2-4
s:web/app.ts#renderGreeting fn  L10-12
$ dctx map read 's:src/util.rs#greet'
# kiosk read
s:src/util.rs#greet fn  src/util.rs
pub fn greet(name: &str) -> String {
    format!("Hello, {}!", title_case(name))
}

For structured consumption, --json puts the same source bytes in source_utf8 (one JSON line, shown verbatim):

$ dctx map read 's:src/util.rs#greet' --json
{"v":2,"place":"kiosk","verb":"read","freshness":{"mode":"strict","state":"verified"},"precision":{"coverage":"syntax","completion":"complete","parser":"dctx-lex-rust/syn-3.0.9"},"records":[{"id":"s:src/util.rs#greet","kind":"fn","path":"src/util.rs","lines":[2,4],"summary":"The greeting shown on the kiosk screen.","summary_source":"doc","signature":null,"span":[44,126],"source_utf8":"pub fn greet(name: &str) -> String {\n    format!(\"Hello, {}!\", title_case(name))\n}","edge":null,"direction":null,"target":null,"confidence":null}],"more":0,"next":null}

Pack for a task#

dctx --help

Usage

verbatim
Usage: dctx <COMMAND> [OPTIONS]
       dctx pack [PATH] [--output PATH] [--clipboard] [--json]
       dctx pack [PATH] --for <TEXT> [--budget TOKENS]
       dctx map <map|find|neighbors|explain|read|skeleton|grep|hubs|path|export> [--json]
       dctx context TARGET [--place PATH] [--budget N] [--json] [--session ID --dedupe]
       dctx rpc
       dctx mcp [PATH]
       dctx serve [--mcp] [PATH]
       dctx read <TARGET> [OPTIONS]
       dctx languages [--json|--markdown]
       dctx doctor [--json]
       dctx cache status [--json] [--root PATH]
       dctx cache gc [--dry-run] [--root PATH] [--max-bytes N]
       dctx cache purge --root PATH [--dry-run] [--yes]
       dctx cache purge --all [--dry-run] [--yes]
       dctx cache config [auto on|off] [--max-bytes N] [--ttl-days N]
       dctx cache auto [--json]
       dctx template build <PATH> [--output PATH]
       dctx template list [--dir PATH]
       dctx plugin search|install|list|info|enable|disable|remove|update|verify
       dctx git <status|protect>

`dctx languages` lists every supported language with its tier: full (symbols and call edges), outline (symbols only) or docs (sections).
`dctx rpc` serves the versioned engine protocol for language packages (send hello first; docs/protocol/README.md).
`dctx mcp` serves the map verbs as MCP tools over stdio (JSON-RPC 2.0, one message per line) for Claude Code, Cursor and Codex.
`dctx serve` and `dctx serve --mcp` use that same server; `dctx read` uses `dctx map read`.
Explicit `dctx pack` writes stdout, the clipboard, or `--output`. It does not create a project text file.
`dctx pack --for <TEXT>` prints task context for an agent card instead: map find, neighbors and read of the names in TEXT, cut to `--budget` estimated tokens (default 3000).
`dctx plugin list` and `dctx --help` do not create a project `.dctx/` directory or start a plugin.
`dctx git` routes to the bundled dctx/git plugin. It is not a Git passthrough.
Cache purge requires `--root PATH` or `--all`, and `--yes` unless `--dry-run` is set.
`dctx cache config` shows the persisted policy. `auto on|off` enables auto-clean, `--max-bytes` tightens the system cap, and `--ttl-days` sets idle overlay and preview lifetime.
`dctx cache auto` prints the last auto-clean time, the bytes it reclaimed and the next due time.
`dctx doctor` lists visible binaries, ownership scopes, SHA-256 checksums and cache sizes without changing the cache or using the network.
pack, map, template, plugin and the TUI run one bounded auto-clean when it is due. They print nothing unless bytes were reclaimed.
`--no-auto-clean` and `DCTX_AUTO_CLEAN=0` disable that slice. `DCTX_CACHE_DIR` selects the cache parent; indexes live in its engine-major.minor subdirectory.

dctx map --help

verbatim
Usage: dctx map <map|find|neighbors|explain|read|skeleton|grep> <TARGET> [OPTIONS]
       dctx map hubs [--limit N] [--json] [--place PATH] [--budget TOKENS] [--meta]
         Most-called symbols (incoming calls and imports, 1..60 lines, default 20) and per-directory file and symbol counts. No TARGET.
       dctx map path <FROM> <TO> [--json] [--place PATH] [--budget TOKENS] [--meta]
         Shortest edge path (calls, imports, contains; either direction; at most 8 hops), one `edge:out|in<TAB>id<TAB>kind<TAB>path` line per hop, or `no path`.
       dctx map export [--format json|mermaid] [--output PATH] [--place PATH]
         The whole graph as one deterministic document (default json: nodes and edges; mermaid: a flowchart of calls and imports). No TARGET, no token cap; --output writes a file.
  TARGET                  Required. map accepts a stable id or a place-relative file.
                          skeleton takes a file (or m:<path>) and prints its declaration signatures, no bodies,
                          in source order: id, kind, L<start>-<end>, signature.
                          A file path is read as m:<path>. Omitting TARGET does not scan.
  --json                  Facade JSON v2, including the precision label
  --place PATH            Place or worktree root (default: current directory)
  --meta                  Restore the snapshot digest and generation in the text header and the snapshot, generation and age_s JSON fields.
                          Without it the answer bytes do not change across unrelated edits or time.
  --profile               Stderr stage timings and the five slowest files. DCTX_PROFILE=1 is the same switch.
  DCTX_MAX_SOURCE_BYTES   Env: total source bytes one scan may read, 1..17179869184 (default 1073741824 = 1 GiB).
  DCTX_MAX_RECORDS        Env: files, symbols and edges one index may hold, 1..100000000 (default 1000000). A bigger place is refused while it is scanned.
  DCTX_MAX_ENTRIES        Env: files and directories one scan may visit, 1..100000000 (default 100000).
  DCTX_FRESHNESS          Env: strict_live hashes every file on a warm start; the default (stamp) trusts a file whose size, mtime and inode are unchanged and older than 2 s.
  --budget TOKENS         Output tokens, 1..2000 (explain max: 1000).
                          Read with no --budget uses the 2,000-token hard cap.
  --depth N               Map: 1..3; neighbors: 1..4. Explain and read take no depth.
  --limit N               Map, find and neighbors page size. Explain and read accept only 1.
  --offset N              Refused. Pass the previous page's next value to --cursor.
  --cursor TOKEN          Opaque continuation. A stale token is rejected.
  --kind fn,type,doc      Find kinds
  --in PATH               Find or grep within a relative path
  grep LITERAL            Exhaustive literal search of indexed files, hits grouped by enclosing symbol
  -i, --ignore-case       Grep: ASCII case-insensitive match
  --edge calls,imports    Neighbor edge filter
  --dir in|out|both       Neighbor direction
  --lines A-B --full      Read those absolute source lines inside the node; full permits 400
  --rev SHA               Refused: this build does not link git
Precision: structural declarations, imports, headings and conservative calls.
Not exact semantic calls, type resolution or macro expansion.
Token estimate ceil(2 * UTF-8 bytes / 7) is not a tokenizer guarantee.
Example: dctx map find 'ignore rules' --json
Example: dctx map map crates/dctx-cli/src/main.rs --depth 2
Example: dctx map map m:crates/dctx-cli/src/main.rs --cursor '<next from the previous page>'
Each verb's own page and example: dctx map <verb> --help
Exit codes: 0 ok, 1 no result (an id not in the index, a binary file), 2 usage, 3 index error; see docs/CLI-EXIT-CODES.md.

dctx languages

verbatim
Usage: dctx languages [--json | --markdown]

Lists every language the map index recognises: name, tag, file names, tier and symbol confidence.
Tiers: full = symbols and call edges (lexical, not type-resolved); outline = symbols only, no call edges promised;
docs = headed sections. Confidence `guess` marks heuristic outlines, whose records carry confidence `guess`.

Options:
  --json        One JSON document with the tiers and the languages
  --markdown    The README language table
  -h, --help    Show this help

Example: dctx languages --json

50 languages: 36 full, 8 outline, 6 docs. The table with every tag and file name is on /languages/.
