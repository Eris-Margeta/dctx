Static checkout guide for contributors and coding assistants. 40 non-fixture Cargo packages: 36 under crates/, one plugin, one desktop, and two standalone tools. Root Cargo.toml includes crates, plugins and desktop; each tool declares its own workspace. bindings/README.md describes planned bindings; root membership for Python/Node is commented out. Fixture manifests under tests are not product crates.

How to read the inventory#

Each row gives purpose, layer, direct first-party path dependencies, and direct external normal dependencies. none means std-only at that crate boundary; first-party only means no direct external normal dependency, not an assertion about the complete dependency closure. Dev/build dependencies are excluded. Optional and target-specific normal dependencies are explicitly marked. Resolved transitive dependencies and runtime behavior are unverified here.

Source convention: for every row named X, purpose is taken from crates/X/src/lib.rs:1 (first six lines), and dependency names from crates/X/Cargo.toml [dependencies]. These two paths are the row's evidence. Exceptions use the directory shown in the row. Desktop purpose comes from apps/dctx-desktop/README.md:3; its lib header has no purpose description. Layer labels are navigation classifications of those headers, using the accepted boundaries in docs/design/ARCHITECTURE-DECISIONS.md (DX-ARCH-01).

Shipped CLI path (v1)#

What the dctx binary (crates/dctx-cli) actually runs, as of v1. No refactor: the other crates stay in the workspace.

  • Shipped: dctx-cli and the crates/dctx facade session (index, find, grep, callers, callees, neighbors, skeleton, hubs, pack, read), with dctx-core (selection), dctx-hash, dctx-ports, dctx-pack, dctx-template, dctx-adapter-cache, dctx-adapter-fs (compatibility IO), dctx-map-model (records and rendering) and the dctx-lex-* extractors.
  • Request types only: dctx-map-query. The CLI imports Request, Verb, Direction, Format, AnswerBudget and EdgeKind; its Index engine is never called.
  • Internal or legacy (compiled as dependencies of dctx-map-query, not run by the CLI): the dctx-map-query Index engine, dctx-map-store, dctx-map-scan, dctx-map-resolve, dctx-map-segment, dctx-adapter-store; dctx-map-parse likewise. docs/SPEC-MAP-MODE.md sections 6–8 and 10 describe this engine.
  • Unstable (no stability promise in v1): dctx-plugin-host, dctx-plugin-platform, dctx-plugin-protocol, dctx-plugin-distribution and dctx-desktop-api. The default dctx-cli build enables the plugin runtime and the bundled Git plugin process; --no-default-features --features strict builds without them.

Linux plugin dependencies are the one target-specific addition above. The facade does not directly depend on dctx-map-query: do not turn an intended architectural boundary into an invented Cargo edge. Its optional Rust extractor uses syntax-rust; plugin runtime dependencies use plugin-runtime.

Language wiring#

Authoritative variants and extension selection: crates/dctx-map-parse/src/domain/facts.rs:8 (Language, for_path). Dispatch: crates/dctx-map-parse/src/adapters/mod.rs:40 (PureParser). Adapter paths below are relative to crates/dctx-map-parse/src/adapters/; each file imports the named lexer. These are all 13 dctx-lex-* packages.

The optional TreeSitterParser in adapters/mod.rs:74 uses grammars for Rust, JavaScript/TypeScript/Tsx and Markdown. Other known languages take the pure adapters; Unknown takes fallback. This is an oracle feature, not the default.

Cross-cutting rules and evidence locations#

  • No Git in the core: product contracts records the core ban and plain-text .gitignore exception. Enforcement evidence: crates/dctx-map-query/tests/no_git.rs (source spawn audit, PATH trap and source-port privacy tests). VCS effects belong to the plugin, not the core.
  • Privacy, selection before content: crates/dctx-adapter-fs/tests/privacy.rs uses read spies to check ignored/omitted paths remain unopened; crates/dctx-map-query/tests/source_privacy.rs checks secrets, ignored files, traversal and symlinks, with an included-file positive control.
  • Pure domain boundary: crates/dctx-core/src/lib.rs:1 points to crates/dctx-core/tests/purity.rs, which checks every source module without a directory exemption. Comments and unit-test tails are excluded from the IO scan. The crate retains its first-party dctx-hash dependency.
  • Plugin PP1–PP10: historical PP matrix maps tests, formal evidence and gaps: PP1 authority narrows; PP2 excluded-source privacy; PP3 effect audit; PP4 protocol binding; PP5 no blind replay; PP6 strict isolation; PP7 bounded resources; PP8 lifecycle progress; PP9 install integrity; PP10 hook order/result truth. The matrix is dated scout evidence, not a fresh passing test result or certification of today's product acceptance.
  • Legacy removal: The migration removed the core IO wrappers and their exports. legacy removal inventory remains the historical inventory; compatibility record maps retired families to retained tests. Pack codecs, template rendering, filesystem adapters and CLI compatibility IO own the replacements. Pure core modules, settings and template assets remain.

Validation commands#

Use TESTING.md for the current commands, toolchains, matrix and exclusions. Desktop backend checks use tools/desktop-check.sh; browser evidence uses bun run e2e from apps/dctx-desktop. A skipped desktop check does not qualify a desktop release. Standalone tools have their own workspaces and checks.
