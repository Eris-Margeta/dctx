dctx turns any folder into the smallest correct context for a task, offline, with byte-stable output that prompt caches can reuse. dctx is an advanced tool with several ways to use it. Used well, it cuts irrelevant text from selected tool answers. It does not save tokens by default; savings depend on a system reusing byte-identical, prefix-stable context. Extra calls can add tokens. If you are new, follow the safe path: one project, the system binary, direct CLI commands. Measure before you change anything.

Under ~200 files, use grep. dctx pays off on large repos, multi-hop questions and many agents sharing one index.

Run dctx agent-setup --format agents (or --format claude) for short rules to paste into AGENTS.md or CLAUDE.md.

Project status#

dctx is not yet stable and not enterprise-ready. It has been in development since January 2026. Until version 2.0, expect breaking changes often. AI providers keep changing how they optimize context on their side; dctx adapts to those changes quickly, but not in real time. Stability is the goal of 2.0, and the project is working toward it: we see an ultimate solution to this problem, and we are denoising it.

dctx began as an internal tool that was never meant to be open-sourced, so parts of it are still messy. It was opened up because colleagues who rely on it needed it in the open, and development continues in public.

The founding promise is zero dependencies. Today dctx still has dependencies. The goal is to become the single best context management tool.

Installation#

System binary — available now. Download the archive for your OS and architecture from GitHub Releases, compare its SHA-256 with the matching entry in SHA256SUMS, extract it, and put dctx (dctx.exe on Windows) on PATH. Archives cover Linux x64/ARM64, macOS x64/ARM64 and Windows x64. Releases after 1.2.0 also ship cosign signatures, a CycloneDX SBOM, build provenance and offline bundles; see verification, provenance and offline installation.

dctx --version

Node wrapper — available on npm from 1.3.1. Run npm install @tejl/dctx to install the Node wrapper and its matching pinned @tejl/dctx-<platform> native package, then npx @tejl/dctx --version to check it. The Python and Go wrappers over dctx rpc are built and tested in CI; use their CI artifacts. The Rust facade is available from tagged Git. Use the release archives for the CLI.

Follow the safe path in ten minutes for one project, CLI setup and whole-session measurement.

Find a symbol, then read it#

Pass the exact ID from find to read to get its metadata and verified source bytes:

$ dctx map find greet
# kiosk find
s:src/util.rs#greet fn  L2-4
s:web/app.ts#renderGreeting fn  L10-12
$ dctx map read 's:src/util.rs#greet'
# kiosk read
s:src/util.rs#greet fn  src/util.rs
pub fn greet(name: &str) -> String {
    format!("Hello, {}!", title_case(name))
}

For structured consumption, --json puts the same source bytes in source_utf8 (one JSON line, shown verbatim):

$ dctx map read 's:src/util.rs#greet' --json
{"v":2,"place":"kiosk","verb":"read","freshness":{"mode":"strict","state":"verified"},"precision":{"coverage":"syntax","completion":"complete","parser":"dctx-lex-rust/syn-3.0.9"},"records":[{"id":"s:src/util.rs#greet","kind":"fn","path":"src/util.rs","lines":[2,4],"summary":"The greeting shown on the kiosk screen.","summary_source":"doc","signature":null,"span":[44,126],"source_utf8":"pub fn greet(name: &str) -> String {\n    format!(\"Hello, {}!\", title_case(name))\n}","edge":null,"direction":null,"target":null,"confidence":null}],"more":0,"next":null}

Which mode?#

  • CLI and one-off chat: pack selected source for a prompt or use the interactive terminal.
  • Agents, short tasks: compare with grep plus narrow file reads first.
  • Agents, long sessions and huge trees: scope the root, find symbols and read exact source.
  • Libraries: embed the Rust facade today; install the Node wrapper with npm install @tejl/dctx, or use CI artifacts for the Python and Go wrappers.
  • CI and prompt caching: pin inputs and measure byte stability and provider cache behavior.
  • Desktop: build the Tauri 0.11 preview; the GPUI rebuild is planned.

Measured, in the open#

The baseline is grep plus reading files.

The 11 November whole-session benchmark measured 20 questions on a private 13-crate Rust workspace with claude-sonnet-5-5, dctx 1.3.0 and three repeats per arm. Median total tokens [min, max]: grep plus reads 14,904,014 [14,604,149, 15,622,381]; dctx CLI (warm index) 14,157,974 [11,221,908, 15,613,375].

On this corpus and model dctx did not save 25 % tokens. CLI median tokens were -5.01 % versus grep; the pre-registered success rule was not met. The claim is accuracy and bounded context, not token savings: CLI named more required files at about equal or higher token cost.

dctx on its own does not save tokens by default. Savings come from a harness or agent system that reuses byte-identical, prefix-stable context across long sessions over a large body of work. It behaves like an advanced caching mechanism, with complete control over every byte of context. There is no measured, citable savings figure for such a system yet. Why this matters.

Official strict citation recall medians [min, max]: grep 10.10 % [10.10, 20.73], CLI 14.46 % [8.36, 22.65]. Diagnostic file-level recall medians: 53.77 % and 71.70 %, respectively; this does not replace strict recall. One corpus, one model, three repeats; no significance claim. Corpus and raw answers are private and cannot be published; dctx 1.3.0 is not current HEAD. Under ~200 files, use grep.

Historical cold indexing of six benchmark corpora took dctx 0.13–1.20 s on one Linux x86_64 runner. This measures CLI wall time, not agent completion time or session cost.

Choosing how to use dctx covers scoping and CLI usage. Measurement evidence describes what was measured (tool-output bytes and estimated tokens); other-tool protocols are retained only as secondary historical notes.

Start and choose your path#

What dctx is, four user paths, responsibilities, and two scopes, one binary explain setup and ownership. The documentation index groups modalities, scopes, engine behavior, reference material, trust and evaluator evidence.

“Smallest correct context” is the goal: selection is lexical and bounded, not a proof of task completeness or a mathematical minimum. Large folders need scoped roots; budgets bound answers, not scans. Provider cache hits and whole-session savings must be measured. See current limits and the specification and roadmap.

The core belief: prompt-processing efficiency#

Send fewer relevant bytes, keep their order stable, and verify exact source. dctx does not use embeddings; it selects lexical symbols and document sections.

  • Bounded: map answers use estimated token budgets and whole records.
  • Deterministic: identical source snapshots and requests give identical bytes.

Read the philosophy and its testable constraints.

Quick Start#

Try a tiny project (POSIX shell; on Windows use Git Bash):

mkdir dctx-demo
cd dctx-demo
printf 'def hello(name):\n    return f"Hello, {name}!"\n' > hello.py
dctx map skeleton hello.py

Use the safe path or the runnable pack and map example. For repeated agent work, see Map mode: context for agents.

Map mode: context for agents#

From this repository's root:

dctx map find "Session"

Read exact IDs from the result with dctx map read 'ID' --json. See the map guide for commands, budgets and limits.

From source#

Requires Rust 1.91 or newer.

git clone https://github.com/Eris-Margeta/dctx
cd dctx
cargo build --locked --release -p dctx-cli
./target/release/dctx-cli --version
alias dctx="$PWD/target/release/dctx-cli"

Cargo builds dctx-cli (dctx-cli.exe on Windows); release archives supply dctx. For a local source installation, use cargo install --locked --path crates/dctx-cli and alias dctx=dctx-cli. On Windows, invoke the executable directly or create a PowerShell alias. See CI coverage and desktop exclusions.

Use as a library#

The public Rust entry point is the dctx facade, available from Git now; crates.io publication is pending.

[dependencies]
dctx = { git = "https://github.com/Eris-Margeta/dctx", tag = "v1.3.1" }

This example is generated from the workspace doctest:

use dctx::{memory::{CancelFlag, FixedClock, MemorySource}, *};
let mut source = MemorySource::new();
source.insert_file("hello.rs", b"pub fn hello() {}\n", 0)?;
let mut session = Session::builder(source).clock(FixedClock(Timestamp(0)))
    .cancellation(std::sync::Arc::new(CancelFlag::new())).ceiling(HostCeiling::base())
    .selection(SelectionPolicy::from_texts(&RuleTexts::default())).grants(HostGrants::PermitAll)
    .storage(StoragePolicy::Ephemeral { max_bytes: 8 * 1024 * 1024 }).place("demo").view("pack").build()?;
let mut output = VecSink::new();
session.pack(&PackRequest::new(), &mut output)?;
println!("{}", std::str::from_utf8(output.as_bytes())?);

The host supplies selection rules and storage policy; FsSource does not load .gitignore automatically. Read the library integration boundary before embedding it. Python, Node and Go wrappers over dctx rpc live in packages/python, packaging/npm and packages/go; they are built and tested in CI. Install the Node wrapper with npm install @tejl/dctx; use CI artifacts for Python and Go.

  --ext <extensions>    Only files with these extensions (comma-separated)
  --binary              Include binary files (omitted by default)
  --empty               Only 0-byte files
  --non-empty           Only files with content
  --large <MB>          Only files larger than this many megabytes
  --small <MB>          Only files smaller than this many megabytes
  --hidden              Only hidden files and directories
  --debug-ignored       List ignored directories without reading them
  --include <pattern>   Only files matching this ignore-rule glob (repeatable)
  --exclude <pattern>   Drop files matching this ignore-rule glob (repeatable)
  --output, -o <path>   Write the page to one file
  --clipboard, -c       Copy the page to the clipboard
  --json                Summary report; with --for, the facade JSON context page
  --tree-stamps=on|off  MOD: timestamp on tree lines (default off; on = the 1.0.0 text)
Task context (agent cards):
  --for <text>          Map find on the names in <text>, then neighbors and read of the best hits
  --budget <tokens>     With --for: estimated-token cap, 100..100000 (default 3000)
  • dctx context returns ranked context for a file, symbol name or stable node id; repeated targets in one call share a delivery session.
  • dctx rpc serves the versioned engine protocol used by the language wrappers (protocol); send hello first.
  • dctx read is dctx map read. dctx map export writes the whole graph as JSON or Mermaid.
  • dctx languages lists every supported language and its tier.
  • dctx doctor lists visible dctx binaries, their scopes, SHA-256 checksums and cache sizes, without network access or cache changes.

Run dctx --help, dctx pack --help and dctx map --help for the complete reference and dctx --version --verbose for feature and precision limits.

See map commands and limits, exit codes, templates, and plugins. Native plugin launch is currently refused by the product host; consent alone does not enable it. Organization policy and dctx policy explain are planned.

Language tiers#

dctx languages prints this table (--json for tools, --markdown for this block) from the one registry that also drives dctx --version --verbose; a test fails when the block below differs from it.

  • full: symbols and call edges. Call edges are lexical, not type-resolved: they come from names, scopes and imports, never from a type checker, and ambiguous references are dropped.
  • outline: symbols only; no call edges are promised. Shell function bodies can yield same-file call guesses, but v1 does not promise shell call edges.
  • docs: headed sections.
  • Confidence: guess marks the heuristic outline families, and every record from those files carries confidence guess; structural means a dedicated lexer or deterministic document rules.

Security & Privacy#

Pack and map run locally and have no telemetry, call no model and make no network calls. Selection happens before any byte is read, hashed, parsed or cached, and is checked again before output leaves the engine.

Rule file Behaviour
.gitignore, .dctxignore, global ignore file Excluded from normal selection; --debug-ignored shows ignored path metadata without reading content

The global ignore file is <config dir>/dctx/ignore: $XDG_CONFIG_HOME/dctx/ignore or ~/.config/dctx/ignore on Linux and macOS, %APPDATA%\dctx\ignore on Windows. dctx does not read Git metadata, so .git/info/exclude and Git's core.excludesFile are not applied: copy those patterns into .dctxignore or the global ignore file when they must keep files out of a pack.

DCTX_INDEX_IGNORED=1 skips those ignore texts, so leave it unset when relying on them. Built-in sensitive-file and .git exclusions still apply.

Sensitive files such as .env, private keys and credentials are omitted from content reads even with ignore negations; pack may list their names. .git at any depth is never listed or read by map, and is never read by pack. Symlinks are never followed; final-component file opens use O_NOFOLLOW. dctx decides by file name only: a secret pasted into an ordinary source file is not detected. Inspect context before sharing it. The privacy contract and deny list and map privacy guide explain the boundary. Report vulnerabilities privately through SECURITY.md.

The release check tests socket activity under strace -f and reports SKIP where tracing cannot run. Plugin network and organization policy designs in the spec include planned features; see current plugin limits.
