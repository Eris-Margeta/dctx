dctx turns any folder into the smallest correct context for a task, offline, with byte-stable output that prompt caches can reuse. dctx is an advanced tool with several ways to use it. Used well, it cuts the context an agent needs to a fraction. Used without a plan, it can add calls and tokens instead of removing them. If you are new, follow the safe path: one project, the system binary, the lean MCP profile. Measure before you change anything.

Find a symbol, then read it#

Pass the exact ID from find to read to get its metadata and verified source bytes:

$ dctx map find greet
# kiosk find
s:src/util.rs#greet fn  L2-4
s:web/app.ts#renderGreeting fn  L10-12

$ dctx map read 's:src/util.rs#greet'
# kiosk read
s:src/util.rs#greet fn  src/util.rs
pub fn greet(name: &str) -> String {
    format!("Hello, {}!", title_case(name))
}

For structured consumption, --json puts the same source bytes in source_utf8 (one JSON line, shown verbatim):

$ dctx map read 's:src/util.rs#greet' --json
{"v":2,"place":"kiosk","verb":"read","freshness":{"mode":"strict","state":"verified"},"precision":{"coverage":"structural","completion":"complete","parser":"dctx-structural/2"},"records":[{"id":"s:src/util.rs#greet","kind":"fn","path":"src/util.rs","lines":[2,4],"summary":"The greeting shown on the kiosk screen.","summary_source":"doc","signature":null,"span":[44,126],"source_utf8":"pub fn greet(name: &str) -> String {\n    format!(\"Hello, {}!\", title_case(name))\n}","edge":null,"direction":null,"target":null,"confidence":null}],"more":0,"next":null}

Which mode?#

  • CLI and one-off chat: pack selected source for a prompt or use the interactive terminal.
  • Agents, short tasks: compare with grep plus narrow file reads first.
  • Agents, long sessions and huge trees: scope the root, find symbols and read exact source.
  • MCP: use the lean profile to start; ACP is planned.
  • Libraries: embed the Rust facade today; pip/npm project libraries are publishing soon.
  • CI and prompt caching: pin inputs and measure byte stability and provider cache behavior.
  • Desktop: build the Tauri 0.11 preview; the GPUI rebuild is planned.

Measured, in the open#

The baseline is grep plus reading files.

A controlled grep-plus-read benchmark that counts whole agent sessions (start-up context, every call, provider cache hits and accuracy) is being prepared; until it is published, dctx makes no whole-session savings claim.

Historical cold indexing of six benchmark corpora took dctx 0.13–1.20 s on one Linux x86_64 runner. This measures CLI wall time, not agent completion time or session cost.

Choosing how to use dctx covers scoping and MCP startup overhead. Measurement evidence describes what was measured (tool-output bytes and estimated tokens); other-tool protocols are retained only as secondary historical notes.

Start and choose your path#

What dctx is, four user paths, responsibilities, and two scopes, one binary explain setup and ownership. The documentation index groups modalities, scopes, engine behavior, reference material, trust and evaluator evidence.

“Smallest correct context” is the goal: selection is lexical and bounded, not a proof of task completeness or a mathematical minimum. Large folders need scoped roots; budgets bound answers, not scans. Provider cache hits and whole-session savings must be measured. See current limits and the specification and roadmap.

The core belief: prompt-processing efficiency#

Send fewer relevant bytes, keep their order stable, and verify exact source. dctx does not use embeddings; it selects lexical symbols and document sections.

  • Bounded: map answers use estimated token budgets and whole records.
  • Deterministic: identical source snapshots and requests give identical bytes.

Read the philosophy and its testable constraints.

Quick Start#

Try a tiny project (POSIX shell; on Windows use Git Bash):

mkdir dctx-demo
cd dctx-demo
printf 'def hello(name):\n    return f"Hello, {name}!"\n' > hello.py
dctx map skeleton hello.py

Use the safe path or the runnable pack and map example. For repeated agent work, see Map mode: context for agents and the MCP client guide.

Map mode: context for agents#

From this repository's root:

dctx map find "SnapshotConfig"

Read exact IDs from the result with dctx map read 'ID' --json. See the map guide for commands, budgets and limits.

From source#

Requires Rust 1.91 or newer.

git clone https://github.com/Eris-Margeta/dctx
cd dctx
cargo build --locked --release -p dctx-cli
./target/release/dctx-cli --version
alias dctx="$PWD/target/release/dctx-cli"

Cargo builds dctx-cli (dctx-cli.exe on Windows); release archives supply dctx. For a local source installation, use cargo install --locked --path crates/dctx-cli and alias dctx=dctx-cli. On Windows, invoke the executable directly or create a PowerShell alias. See CI coverage and desktop exclusions.

Use as a library#

The public Rust entry point is the dctx facade, available from Git now; crates.io publishing soon.

[dependencies]
dctx = { git = "https://github.com/Eris-Margeta/dctx", tag = "v1.2.0" }

This example is generated from the workspace doctest:

use dctx::{memory::{CancelFlag, FixedClock, MemorySource}, *};
let mut source = MemorySource::new();
source.insert_file("hello.rs", b"pub fn hello() {}\n", 0)?;
let mut session = Session::builder(source).clock(FixedClock(Timestamp(0)))
    .cancellation(std::sync::Arc::new(CancelFlag::new())).ceiling(HostCeiling::base())
    .selection(SelectionPolicy::from_texts(&RuleTexts::default())).grants(HostGrants::PermitAll)
    .storage(StoragePolicy::Ephemeral { max_bytes: 8 * 1024 * 1024 }).place("demo").view("pack").build()?;
let mut output = VecSink::new();
session.pack(&PackRequest::new(), &mut output)?;
println!("{}", std::str::from_utf8(output.as_bytes())?);

The host supplies selection rules and storage policy; FsSource does not load .gitignore automatically. Read the library integration boundary before embedding it. Python and Node project wrappers are planned.

CLI Reference#

Usage: dctx [PATH] [OPTIONS]
       dctx pack [PATH] [--output PATH] [--clipboard] [--json] [--tree-stamps=on|off]
       dctx pack [PATH] --for <TEXT> [--budget TOKENS]
       dctx map <map|find|neighbors|explain|read> <TARGET> [--json]
       dctx cache status|gc|purge|config|auto
       dctx template build <PATH> | template list
       dctx plugin search|install|list|info|enable|disable|remove|update|verify|run
       dctx git <status|protect>

Snapshot options:
  -c, --clipboard       Copy to clipboard
  -d, --diff            Output the diff only (if available)
  -t, --tree            Tree only (skips file content)
  -r, --reset           Force V1 reset
  --tree-stamps=on|off  MOD: and SIZE: on tree lines (default off; on = the 1.0.0 text)

Filter options:
  --ext <list>          Only these extensions, e.g. rs,toml
  --binary              Include binary files (excluded by default)
  --empty | --non-empty Only empty / non-empty files
  --large <MB> | --small <MB>
  --hidden              Only hidden files and folders
  --debug-ignored       Show ignored paths without reading them

Run dctx --help for the complete reference and dctx --version --verbose for feature and precision limits.

See map commands and limits, MCP profiles, exit codes, templates, and plugins. Native plugin launch is currently refused by the product host; consent alone does not enable it. Organization policy and dctx policy explain are planned.

Language tiers#

dctx languages prints this table (--json for tools, --markdown for this block) from the one registry that also drives dctx --version --verbose; a test fails when the block below differs from it.

  • full: symbols and call edges. Call edges are lexical, not type-resolved: they come from names, scopes and imports, never from a type checker, and ambiguous references are dropped.
  • outline: symbols only; no call edges are promised. Shell function bodies can yield same-file call guesses, but v1 does not promise shell call edges.
  • docs: headed sections.
  • Confidence: guess marks the heuristic outline families, and every record from those files carries confidence guess; structural means a dedicated lexer or deterministic document rules.

Security & Privacy#

Pack, map and MCP run locally and have no telemetry, call no model and make no network calls. Selection happens before any byte is read, hashed, parsed or cached, and is checked again before output leaves the engine.

Rule file Behaviour
.gitignore, .dctxignore, global ignore Excluded from normal selection; --debug-ignored shows ignored path metadata without reading content

DCTX_INDEX_IGNORED=1 skips those ignore texts, so leave it unset when relying on them. Built-in sensitive-file and .git exclusions still apply.

Sensitive files such as .env, private keys and credentials are omitted from content reads even with ignore negations; pack may list their names. .git at any depth is never listed or read by map, and is never read by pack. Symlinks are never followed; final-component file opens use O_NOFOLLOW. dctx decides by file name only: a secret pasted into an ordinary source file is not detected. Inspect context before sharing it. The privacy contract and deny list and map privacy guide explain the boundary. Report vulnerabilities privately through SECURITY.md.

The release check tests socket activity under strace -f and reports SKIP where tracing cannot run. Plugin network and organization policy designs in the spec include planned features; see current plugin limits.
