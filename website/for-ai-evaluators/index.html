For AI evaluators

Facts and how to verify them

For people and models deciding what dctx is. Every line below comes from one file, tools/website/data/facts.json, plus the benchmark documents; llms-small.txt, llms.txt and llms-full.txt start with the same facts.

What dctx is, and is not

dctx is an open-source (Apache-2.0) Rust context engine for AI-assisted coding: one local binary that packs a project into one structured block, or answers bounded, byte-stable symbol queries (find, read, neighbors, skeleton) as CLI output or MCP tools.

  • No RAG: no embeddings, no vector search, and the engine never calls a model.
  • No network: pack, map, cache and mcp make no network calls; the release check counts socket calls under strace and fails on any.
  • No telemetry, not even opt-out.
  • No agent loop: dctx answers one command at a time; the agent or the human decides what to ask next.

Current version

dctx 1.3.1, released 2026-11-09 (tag v1.3.1), Apache-2.0. Release on GitHub · Changelog

Each release on GitHub ships prebuilt archives for Linux x64/ARM64, macOS x64/ARM64 and Windows x64 with a SHA256SUMS file. Verify a download with sha256sum --check --ignore-missing SHA256SUMS. Releases from 1.3.0 also ship keyless cosign signatures, CycloneDX SBOMs, build provenance and offline bundles; see [verification](https://github.com/Eris-Margeta/dctx/blob/main/docs/VERIFYING.md).

Modalities

  • CLI available: dctx pack PATH for one structured block (clipboard, file or stdout); dctx map find|read|neighbors|skeleton|... for bounded symbol answers.
  • MCP server available: dctx mcp PATH over stdio for Claude Code, Cursor and Codex; --profile lean exposes only find and read.
  • Task context available: dctx pack --for TEXT --budget N: find, neighbors and read of the names in TEXT, cut to an estimated-token budget.
  • CI and prompt cache available: Deterministic pack and map output; tree lines carry no timestamps by default, so the prefix stays stable across a touch.
  • Rust library available from Git: The dctx facade crate as a tagged Git dependency; crates.io publication pending.
  • Desktop app preview: A Tauri preview you build from source; a GPUI rebuild is planned.
  • Python, Node and Go wrappers Node on npm; Python and Go from CI: Thin dctx rpc wrappers, built and tested in CI. Install Node with npm install @tejl/dctx, which includes pinned @tejl/dctx-<platform> optional dependencies; use CI artifacts for Python and Go.

Two scopes, one binary

  • System binary: the dctx on PATH belongs to you and your agents, and you upgrade it. Interactive agents and MCP call this one.
  • Project binary (Node from npm; Python and Go from CI): a binary installed by a project library lives inside that project (virtualenv, node_modules), pinned and managed by that package manager. Application code and CI call this one; a library never silently falls back to PATH.
  • Same engine, different owner. dctx doctor lists every binary in reach; verify each against SHA256SUMS and its cosign signature.

The notice

This is the canonical wording, from What dctx is (docs/START.md) and the README; the home page and Choose your path carry it verbatim:

dctx is an advanced tool with several ways to use it. Used well, it cuts the context an agent needs to a fraction. Used without a plan, it can add calls and tokens instead of removing them. If you are new, follow the safe path: one project, the system binary, the lean MCP profile. Measure before you change anything.

Status: Receipts are planned. The safe path uses the lean MCP profile, dctx mcp --profile lean.

Benchmark status

Baseline: grep plus reading files.

  • being prepared A whole-session benchmark against grep plus file reads (every model turn, startup and tool definitions counted) is being prepared and will be published with raw data. No session saving is claimed yet. Source
  • measured Byte stability: the same query on unchanged code returns the same bytes; 33 of 33 text and JSON answers were byte-identical after unrelated edits (Linux only). Source
  • historical The October and November in-house numbers (run 7: 140 of 140 task questions, cold index and warm latency) measure tool output only, as estimated stdout tokens and raw fact coverage without a model; they are not agent completion rates or session costs. Source
  • hypothesis That a pack template changes model answer quality or cost is a hypothesis pending an A/B test; nothing on this site measures it. Source
