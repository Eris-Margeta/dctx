Our core belief

Prompt‑processing efficiency is the product.

Every token in front of a model is paid for three times — in prefill, in cache misses and in attention. dctx is engineered to cut all three.

Prefill

A model must process every input token before it answers — you pay for each one and wait for it. dctx answers with exact spans and diffs instead of whole files, inside a hard budget.

Cache hits

Providers serve repeated prompt prefixes at a fraction of the price and latency, but one changed byte breaks the cache. dctx answers are deterministic and canonically ordered: the same tree and question give the same bytes. Some answer headers still change after unrelated edits; prefix-stable answers are next on the roadmap.

Attention

Answers get worse as irrelevant tokens pile up. dctx ranks and bounds every answer and labels it with its precision and freshness, so a model reasons over facts, not guesses.

Accuracy

Zero RAG defects, measured row by row.

Retrieval over embedded chunks fails in predictable ways. dctx does not use embeddings: it answers from a lexical index of syntax-owned spans and checks bytes before it emits them. The specification names ten defect classes; this is where each one stands in the current development line.

Security & privacy

Built for codebases you cannot afford to leak.

Ignored means never read

Files excluded by .gitignore, .dctxignore or policy are classified before a single byte is opened, hashed or cached — enforced by read-spy tests.

No network, no VCS in the core

The core never opens a socket, never runs git and never reads .git/. Identity comes from dctx's own content digest.

Plugins behind a boundary

Outside effects are designed to run in out-of-process plugins with explicit capabilities, consent and receipts, and distributions verify with Ed25519. Until a qualified launcher exists, the host refuses native plugin launch on every OS, the bundled Git plugin included.

Known issue: dctx pack includes .env files unless they are ignored. Add .env* to .dctxignore until the default changes.

Organization control

One signed policy, from the board to the terminal.

The specification extends the language that defines dctx output templates to selection, budgets, parsers, cache limits, plugins and privacy for every mode. Seven layers; each can only narrow the one above it.

  • Narrowing only. A team or developer that tries to widen a company rule gets a precise error, never a silent override.
  • Signed bundles. Distribute one verified policy file through your device management to every machine.
  • Explainable. dctx policy explain will show every effective value and the layer that set it.

Roadmap Output templates and organization ceilings in the template compiler exist today. The seven-layer signed lattice and dctx policy are specified, not shipped.

Questions

Answers for decision makers.

Does any of our source code leave our network?

No. dctx runs on your machines. The CLI has no telemetry, no network client and never calls a model. What reaches a model is exactly what your developers or agents choose to send, already bounded by your policy.

How is dctx different from retrieval-augmented generation?

dctx does not use embeddings or vector search. It builds a lexical index of your code from syntax, answers with whole spans whose bytes are checked against their digest, in a deterministic order, and labels every answer with its precision and freshness. That removes the typical failure modes of chunk retrieval and keeps prompts cache-friendly.

Which languages does it understand?

Fourteen language families with structural extractors: Rust, JavaScript, TypeScript and TSX, Python, Go, Java, C and C++, C#, Kotlin, Ruby, PHP, Swift, Markdown, and JSON, TOML and YAML configuration. This is declaration structure, not full compiler semantics; other files are reported as opaque, never guessed at.

Does it work with the AI tools our teams already use?

Yes. dctx works through the shell that every coding agent already has, through the clipboard for chat assistants, and as a library. An MCP server and agent hooks are specified on the roadmap; neither ships today.

What is the difference between open source and Enterprise?

The open repository is Apache-2.0 and ongoing work; parts of it still use third-party dependencies, which we do not consider enterprise-ready. Enterprise licensing provides enterprise-ready builds, organization and tenant policy control and signed policy distribution as they land, and direct support, from €45,000 per company per year.
