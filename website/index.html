Context, engineered.

dctx gives a model the fewest, most relevant bytes of your code, in an order that stays the same between turns. Deterministic, bounded and offline.

How it works

Four steps, every one checkable. The scene above runs them on the 13-file sample.

  1. Select before reading.

    Ignore rules and the built-in deny decide which files exist for dctx before a byte is read, hashed, parsed or cached. In the sample, target/ and the binary assets/logo.png are left out, and .env is listed by name only. README

  2. Index syntax, not chunks.

    Files become syntax-owned symbols, modules and headings with lexical call and import edges. No embeddings and no vector store; edges carry a confidence label. README

  3. Answer within a budget.

    Every answer fits an estimated token budget (up to 2,000; explain up to 1,000) and never splits a record. pack --for on the sample used 223 of 600 tokens and dropped 0. README

  4. Same bytes every time.

    The same tree and question give the same bytes, so prompt caches hit. Default answers carry no timestamps, digests or ages; --meta restores them. README

A conforming implementation must satisfy five constraints. Status as the specification states it:

SPEC §2
ConstraintDefinitionStatus
BoundedEvery answer has a declared byte and estimated-token ceiling, reserved before records are written; records are never splitlanded
DeterministicSame source snapshot, policy, plan, ranking revision and request ⇒ identical bytes, on every OS and thread countlanded on Linux
Prefix-stableContext injected across turns is layered so that bytes that did not need to change do not change (§12)tier layering remains target
Non-redundantWithin one session a record already delivered is not re-sent unless its content changed (§12.4)target
HonestEvery answer states its freshness, precision and provenance; the engine never asserts what it does not knowlanded

Ignored means never read

  • Ignore rules first. .gitignore, .dctxignore and a global ignore exclude files before they are opened. README
  • A built-in deny with no override. Env files, private keys, credential and secret files are listed by name but never read. README
  • .git is closed. Never listed or read by the map verbs, never read by pack. README
  • No symlink escapes. Files open with O_NOFOLLOW; symlinked directories are never entered. README
  • Local only. No telemetry, no model calls, no network for pack and map. README

dctx decides by file name: a secret pasted into an ordinary source file is not detected. On the sample, map grep example does not find the .env value, which contains that word. README
