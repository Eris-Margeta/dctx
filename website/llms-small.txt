# dctx

> dctx turns any folder into the smallest correct context for a task, offline, with byte-stable output that prompt caches can reuse. dctx is an advanced tool with several ways to use it. Used well, it cuts irrelevant text from selected tool answers. It does not save tokens by default; savings depend on a system reusing byte-identical, prefix-stable context. Extra calls can add tokens. If you are new, follow the safe path: one project, the system binary, direct CLI commands. Measure before you change anything.

## Facts

### What dctx is

dctx is an open-source (Apache-2.0) Rust context engine for AI-assisted coding: one local binary that packs a project into one structured block, or answers bounded, byte-stable symbol queries (find, read, neighbors, skeleton) as CLI output.

What it is not:

- No RAG: no embeddings, no vector search, and the engine never calls a model.
- No network: pack, map and cache make no network calls; the release check counts socket calls under strace and fails on any.
- No telemetry, not even opt-out.
- No agent loop: dctx answers one command at a time; the agent or the human decides what to ask next.

### Version and download

- Current version: 1.3.2, released 2026-11-22 (tag `v1.3.2`): https://github.com/Eris-Margeta/dctx/releases/tag/v1.3.2
- Each release on GitHub ships prebuilt archives for Linux x64/ARM64, macOS x64/ARM64 and Windows x64 with a SHA256SUMS file.
- Verify a download: `sha256sum --check --ignore-missing SHA256SUMS`
- Releases from 1.3.0 also ship keyless cosign signatures, CycloneDX SBOMs, build provenance and offline bundles; see [verification](https://github.com/Eris-Margeta/dctx/blob/main/docs/VERIFYING.md).

### Modalities

- CLI (available): `dctx pack PATH` for one structured block (clipboard, file or stdout); `dctx map find|read|neighbors|skeleton|...` for bounded symbol answers. https://www.dctx.internet.technology/cli/
- Task context (available): `dctx pack --for TEXT --budget N`: find, neighbors and read of the names in TEXT, cut to an estimated-token budget. https://www.dctx.internet.technology/docs/map-mode/
- CI and prompt cache (available): Deterministic pack and map output; tree lines carry no timestamps by default, so the prefix stays stable across a touch. https://www.dctx.internet.technology/docs/modalities/#ci--prompt-cache-prefix-stability
- Rust library (available from Git): The `dctx` facade crate as a tagged Git dependency; crates.io publication pending. https://www.dctx.internet.technology/docs/modalities/#rust-library-embed-the-facade
- Desktop app (preview): A Tauri preview you build from source; a GPUI rebuild is planned. https://www.dctx.internet.technology/docs/modalities/#desktop-app-tauri-preview-today
- Python, Node and Go wrappers (Node on npm, Python wheels from CI, Go from source): Thin `dctx rpc` wrappers tested in CI. Install Node with `npm install @tejl/dctx@1.3.2 --save-exact` for the matching pinned `@tejl/dctx-<platform>` optional dependency. Install Python from matching wrapper and platform CI wheels. Use Go from a `v1.3.2` source checkout with a local `replace` in `go.mod` and supply the matching `1.3.2` engine via `DCTX_BIN`. https://www.dctx.internet.technology/docs/modalities/#python-node-and-go-wrappers

Two scopes, one binary:

- System binary: the `dctx` on PATH belongs to you and your agents, and you upgrade it. Interactive agents call this one.
- Project binary: the application and its CI use the engine pinned by the project. Node's npm package and Python's CI wheels can install the matching native binary in node_modules or the virtualenv, respectively. With Go from a source checkout and local `replace`, the project supplies the matching engine explicitly. The wrappers never silently fall back to PATH.
- Same engine, different owner. `dctx doctor` lists every binary in reach; verify each against SHA256SUMS and its cosign signature.

### Benchmarks

Baseline: grep plus reading files.

- Measured: On 12 November 2026, the whole-session study used claude-sonnet-5-5 across 20 questions and three repeats per arm (300 graded answers across five arms). The dctx harness-prefix pack (P) reached 70.91% median strict citation recall versus 19.34% for grep plus file reads (A). Median list-price cost per question was $0.195418 for P and $0.179670 for A (+8.8% for P), pricing uncached input, cache creation, cache reads and output separately. P met the recall requirement and missed the prespecified 15% cost reduction, so it did not win the benchmark. https://www.dctx.internet.technology/benchmarks/#grep-read
- Measured: Byte stability was measured on Linux only. All 33 text answers and all 33 JSON answers were byte-identical after unrelated edits and across five separate invocations. https://www.dctx.internet.technology/docs/stability/
- Historical: October 2026 run 7 covered 70 task questions. dctx scored 140/140 points and returned 353/354 gold facts. The protocol scores raw tool output without a model and estimates tokens from stdout bytes. https://www.dctx.internet.technology/benchmarks/#run7
- Hypothesis: The whole-session benchmark compares tool and harness configurations. Isolating the effect of a pack template requires a separate A/B test. https://www.dctx.internet.technology/templates/

### Removed in 1.2.0

These existed before 1.2.0 and no longer work. A transcript that uses them describes an old version.

- `dctx PATH` (the implicit snapshot command, for example `dctx .`): use `dctx pack PATH`.
- the top-level snapshot flags `-d`/`--diff`, `-t`/`--tree` and `-r`/`--reset`: use `dctx pack PATH` with its filters.
- the project rule files `.legacyignore` and `.dctxomitcontent`: use `.gitignore` and `.dctxignore`.
- `dctx cache gc --legacy` and its export-selection flags: use `dctx cache gc`.

- Test suite: `cargo test --workspace --locked --exclude dctx-desktop --exclude dctx-desktop-api` https://github.com/Eris-Margeta/dctx/blob/main/docs/TESTING.md
- CI: CI runs on pushes to main, pull requests and manual dispatch (optional stage range and test filter). The full test matrix pairs each OS label (`ubuntu-24.04`, `macos-15`, `macos-15-intel`, `windows-2022`) with stable Rust and MSRV 1.91 for eight jobs. Linux test jobs use self-hosted dctx-fast runners for upstream pushes and GitHub-hosted runners for pull requests, fork runs and manual dispatch. The Linux quality job uses GitHub-hosted ubuntu-24.04. https://github.com/Eris-Margeta/dctx/actions
- No network calls: `scripts/release-check.sh --quick target/release/dctx-cli` https://github.com/Eris-Margeta/dctx/blob/main/scripts/release-check.sh
- Byte stability: `python3 docs/research/stability-20261105/verify.py` https://www.dctx.internet.technology/docs/stability/
- Historical benchmark: `docs/research/bench-3way-20261030/run-3way.sh target/release/dctx-cli` https://github.com/Eris-Margeta/dctx/tree/main/docs/research/bench-3way-20261030
